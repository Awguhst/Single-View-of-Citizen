info
Everything here is synthetic. Eleven government agencies each hold their own records of the same people, with no shared ID and the usual data-quality problems. The pipeline links those records into one profile per citizen. This page shows the shape of the result; Evaluation shows how accurate it is.

Review Queue

Resolved profiles worth a second look, worst first. An Isolation Forest ranks profiles by how unusual their linkage pattern is - never their demographics - and each row shows both what the model reacted to and the actual conflicting values a reviewer can act on.

lightbulb
What you are actually looking at. On this dataset an "unusual profile" is almost always a linkage artefact rather than an unusual citizen - two people merged into one profile, or one person split across several. Measured against the known ground truth, this ranking surfaces 61% of all real linkage errors inside the top 5% of the population (25x better than picking at random). The old "lowest match confidence" queue was dropped because confidence is effectively constant here - it ranked on noise. See Evaluation for that comparison.

Model Evaluation

Every model in this application, scored against the synthetic ground truth

science
Why these numbers can exist at all. The data is synthetic, so the true identity behind every record is known (records.person_index). The linkage pipeline never sees it - it resolves identity from noisy fields alone, exactly as a production system would - but this page can use it afterwards to check the result. These are the only endpoints in the application that read ground truth; no citizen-facing page depends on them.

Is the model beating a hand-written rule?

An F1 in isolation says nothing. Each baseline below is a deterministic rule someone would reach for before installing a probabilistic linkage engine; the two degenerate rows bracket the scale.

Clustering threshold trade-off

The shipped threshold is one hand-picked number. Each point re-clusters the stored pairwise edges - no retraining - and scores the result against ground truth.

Robustness to data quality

The whole pipeline re-run against progressively worse data. A probabilistic model should pull further ahead of a fixed rule as the data degrades - if the gap stays flat, the complexity is not earning its keep. Nothing here touches the live dataset.

Which anomaly detector actually finds linkage errors?

Unsupervised detection normally cannot be scored. Here it can: a cluster either does or does not correspond one-to-one with a real citizen, which gives a checkable ranking task. This is the reason more than one algorithm exists in the codebase - each fails differently, and the comparison is the point.
